How is this judged?

How far each submodule pin lags its upstream default branch, and when its parent last moved it: read from the last stored scan, judged today. A scan runs after every poll and measures the last stored walk (walk a configuration first to see a new commit){% if not local %}; to scan by hand run nanosoc-rm freshness scan --store on a login server{% endif %}.

Outdated: {{ OUTDATED_BEHIND }} or more commits behind the upstream default branch, or behind and not bumped for {{ OUTDATED_DAYS }} days. Behind: 1 to {{ OUTDATED_BEHIND - 1 }} behind. Unpushed: no branch or tag on any host holds the pinned commit. Not measured: the commits behind could not be counted (the reason is on the pin).

A tree's verdict is its worst direct pin. Updated = days since anyone last moved a pin in the tree: Fresh under {{ FRESH_DAYS }} d, Aging {{ FRESH_DAYS }} to {{ STALE_DAYS - 1 }} d, Stale {{ STALE_DAYS }} d or more. A frozen silicon tree is old on purpose: it shows what it would be, is never counted as outdated, and its age is how long ago it was frozen, with no Fresh/Aging/Stale grade.
